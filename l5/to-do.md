# Задание

Две практики — по одной на каждое занятие урока.

## Часть 1. Классы предметов (склад/библиотека)

Фундамент CLI-менеджера инвентаря — классы предметов. ООП здесь ради задачи:
предмет обязан хранить свой инвариант (склад не уходит в минус), а каталог
должен печататься полиморфно, не зная конкретных типов.

1. **`Item`** — базовый класс. Поля: `item_id` (str, инвентарный номер),
   `name` (str), `quantity` (int, храни в `self._quantity`). **Инкапсуляция**:
   количество меняется только методами `restock(n)` (добавить `n` штук, `n > 0`
   иначе `ValueError`) и `take(n)` (забрать `n` штук, `1 <= n <= остаток` иначе
   `ValueError`) — снаружи количество читают, но не пишут напрямую. Метод
   `label()` — строка для каталога вида `f"[{item_id}] {name} — {quantity} шт."`
   — это полиморфная точка, подклассы её дополнят.
2. **Dunder-методы у `Item`**: `__repr__` (для отладки, `type(self).__name__`
   даст имя реального класса), `__eq__` (равны, если совпадает `item_id`),
   `__hash__` (согласован с `__eq__`, чтобы класть объекты в `set`), `__lt__`
   (сравнение по `name`, чтобы работал `sorted()`).
3. **`Book(Item)`** — добавляет поле `author`. Вызывает `super().__init__(...)`,
   переопределяет `label()`: к базовой строке добавляет `, автор: <author>`.
4. **`Tool(Item)`** — добавляет поле `condition` (по умолчанию `"новый"`).
   Тоже переопределяет `label()`, добавляя `, состояние: <condition>`.
5. **`print_catalog(items)`** — принимает список разных предметов и печатает
   `label()` каждого. Цикл не должен знать конкретный тип — просто дёргает
   `it.label()` для всех.

## Часть 2. Геокаталог публичных IP-адресов

ООП на реальных данных: превращаем сырые данные об IP-адресах в объекты,
раскладываем по классам (категоризация) и считаем статистику.

[ip-api.com](http://ip-api.com/json) — бесплатный геолокационный API, ключ не
нужен. Запрос вида `http://ip-api.com/json/{ip}?fields=...` возвращает JSON с
полями: `country`, `countryCode`, `regionName`, `city`, `lat`, `lon`,
`timezone`, `isp`, `org`, `as`, `mobile`, `proxy`, `hosting` (последние три —
булевы флаги) и `status` (строка `"success"` при удаче). Принимает только
**публичные** IP — приватные/служебные адреса (`127.0.0.1`, `192.168.x.x`,
`10.x.x.x` и т.п.) отклони сам ещё до запроса, через `ipaddress.ip_address(ip).is_global`.

Что написать:

1. **`fetch_ip_info(ip)`** — запрос к API, возвращает сырой JSON как `dict`.
   Таймаут обязателен. Приватный IP — `ValueError` без похода в сеть; `status`
   в ответе не `"success"` — исключение с текстом из поля `message`.
2. **Иерархия классов** с именами ровно такими:
   - `Host` — базовый класс, хранит адрес, страну, город, координаты (`lat`/`lon`),
     провайдера, ASN, континент. `category()` возвращает название типа строкой
     (у базового — что-то на случай, если ни один флаг не подошёл).
   - `DataCenterHost(Host)` — `hosting == True`.
   - `MobileHost(Host)` — `mobile == True`.
   - `ProxyHost(Host)` — `proxy == True`.
   - `ResidentialHost(Host)` — все три флага `False`.
   
   Сам реши, какой флаг приоритетнее, если вдруг несколько истинны одновременно.
3. **Фабрика**: `classmethod Host.from_raw(raw)` смотрит на флаги в сыром
   словаре и создаёт объект нужного подкласса — чтобы в `demo()` не писать
   `if/elif` по каждому IP.
4. **`HostCatalog`** — содержит хосты внутри (композиция, не наследует
   `list`/`dict`). Методы: `add(host)` (без дублей по IP), `by_country(name)`
   (список хостов из страны), `stats()` (словарь `{категория: количество}` по
   `host.category()`). Dunder-методы, чтобы работали `len(catalog)`,
   `for host in catalog`, `"1.1.1.1" in catalog`.
5. **`demo()`**: прогоняет список публичных IP через `fetch_ip_info` и
   `Host.from_raw`, складывает в `HostCatalog`, печатает для каждого IP страну/
   провайдера/`category()`, печатает `stats()`, и для страны первого хоста —
   все хосты оттуда через `by_country()`.

Несколько публичных IP для проверки: `8.8.8.8` (Google DNS), `1.1.1.1`
(Cloudflare DNS), `208.67.222.222` (OpenDNS), `9.9.9.9` (Quad9 DNS) — все из
дата-центров; возьми ещё пару адресов на свой вкус для разнообразия категорий.

# Урок L6. Декораторы и парсинг HTML (BeautifulSoup)

Декораторы уже встречались дважды: в L4 мы выяснили, что функция — обычный
объект, который можно передавать и возвращать, а в L5 пользовались готовыми
`@classmethod`, `@staticmethod` и `@property`, не разбирая, как они устроены.
Пора закрыть пробел: **декоратор — это функция, которая принимает функцию и
возвращает функцию**. Вся «магия» строчки с `@` — синтаксический сахар поверх
замыканий из L4.

Второй блок урока — **парсинг HTML** библиотекой `BeautifulSoup` (bs4). Это
рабочая лошадка для вытаскивания данных из веб-страниц: CSS-селекторы, текст,
атрибуты. В практике обе темы сойдутся: будем парсить новости с официального
сайта Коврова, а все функции-добытчики защитим собственными декораторами.

# Блок 1. Декораторы

## 1. Напоминание: вложенные функции и замыкания

Файл: [01_nested_functions.py](01_nested_functions.py)

Декоратор невозможно понять без двух фактов из L4.

**Факт 1. Функция — объект.** Её можно положить в переменную, передать
аргументом, вернуть из другой функции:

```python
def shout(text):
    return text.upper() + "!"

f = shout          # без скобок — взяли саму функцию
f("привет")        # 'ПРИВЕТ!'
```

**Факт 2. Вложенная функция захватывает переменные внешней** — это замыкание.
Захваченная переменная живёт столько же, сколько возвращённая функция:

```python
def multiplier(factor):
    def inner(x):
        return x * factor      # factor захвачен из multiplier
    return inner

double = multiplier(2)
double(5)                      # 10 — factor=2 «живёт» внутри double
```

Если нужно **изменять** захваченную переменную (например, счётчик вызовов) —
объявляй её `nonlocal` внутри вложенной функции, иначе присваивание создаст
новую локальную переменную.

Держи в голове картинку: **внешняя функция — это фабрика, она настраивает и
возвращает внутреннюю**. Декоратор — ровно такая фабрика, только на вход она
получает функцию.

## 2. Свои декораторы

Файл: [02_own_decorators.py](02_own_decorators.py)

### Что делает `@`

Декоратор принимает функцию и возвращает её замену — обычно «обёртку», которая
что-то делает до и/или после вызова оригинала:

```python
def log_calls(function):
    def wrapper(*args, **kwargs):
        print(f"вызов {function.__name__}{args}")
        result = function(*args, **kwargs)
        print(f"результат: {result}")
        return result
    return wrapper

@log_calls
def add(a, b):
    return a + b
```

Строка `@log_calls` — это **в точности** запись:

```python
def add(a, b):
    return a + b

add = log_calls(add)     # имя add теперь указывает на wrapper
```

Никакой новой механики: вызвали `log_calls`, передали `add`, получили `wrapper`,
перепривязали имя. После этого `add(2, 3)` на самом деле вызывает `wrapper(2, 3)`,
а тот внутри — оригинальный `add`, захваченный замыканием.

Разберём анатомию `wrapper`:

- `*args, **kwargs` — обёртка не знает и не хочет знать сигнатуру оборачиваемой
  функции, поэтому принимает что угодно и пробрасывает как есть (L4, тема 1 —
  там мы и обещали, что это «фундамент декораторов»);
- `return function(*args, **kwargs)` — **не забывай `return`**. Классическая
  ошибка: обёртка вызывает функцию, но не возвращает результат, и все
  декорированные функции молча возвращают `None`;
- `return wrapper` — внешняя функция возвращает обёртку, не вызывая её
  (без скобок).

### Декораторы на методах класса

Метод — та же функция, просто первым позиционным аргументом приходит `self`.
А `self` спокойно проедет через `*args`, поэтому **тот же самый декоратор
работает и на методах** без единого изменения:

```python
class Cart:
    @log_calls
    def add_item(self, name, price):
        ...
```

С `@classmethod`, `@staticmethod` и `@property` из L5 теперь тоже всё прозрачно:
это декораторы из стандартной библиотеки, которые подменяют функцию специальным
объектом-дескриптором. Синтаксис один и тот же.

### Несколько декораторов

Декораторы применяются **снизу вверх** (ближний к функции — первым):

```python
@outer
@inner
def f(): ...
# то же, что f = outer(inner(f))
```

## 3. Декораторы с параметрами и functools.wraps

Файл: [03_params_wraps.py](03_params_wraps.py)

### Третий уровень вложенности

Часто декоратору нужна настройка: какое сообщение печатать, сколько раз
повторять, что вернуть при ошибке. Но в строке `@log_calls` декоратор получает
**только функцию** — параметры передать некуда. Решение: добавить ещё один
внешний уровень — **фабрику декораторов**, которая принимает параметры и
возвращает уже настроенный декоратор.

Типичный рабочий пример — декоратор, который не даёт функции уронить программу:
любое исключение ловится, печатается заданное сообщение, а наружу уходит `False`:

```python
def file_decorator(errormessage):              # 1) фабрика: принимает ПАРАМЕТРЫ
    def internal_decorator(function):          # 2) декоратор: принимает ФУНКЦИЮ
        def wrapper(*args, **kwargs):          # 3) обёртка: принимает АРГУМЕНТЫ вызова
            try:
                return function(*args, **kwargs)
            except Exception as e:
                print(errormessage)
                print(e)
                return False
        return wrapper
    return internal_decorator

@file_decorator("не удалось прочитать файл")
def read_config(path):
    with open(path) as f:
        return f.read()
```

Уровни легко запомнить по тому, **что** на каждом приходит на вход: параметры ->
функция -> аргументы вызова. Запись `@file_decorator("...")` — это два вызова
подряд:

```python
read_config = file_decorator("не удалось прочитать файл")(read_config)
#             ^ вернул internal_decorator              ^ вернул wrapper
```

Обрати внимание: `errormessage` захвачен замыканием через **два** уровня — и
`internal_decorator`, и `wrapper` его видят. Это всё та же механика из темы 1.

Когда такой декоратор уместен: пакетная обработка (сто файлов, упал один — лог
и едем дальше), необязательные шаги. Когда нет: если вызывающему коду важно
**различать** ошибки — глотать `Exception` целиком и возвращать `False`
означает потерять информацию о том, что случилось.

### functools.wraps

У обёртки есть побочный эффект: декорированная функция **теряет своё имя
и докстринг** — снаружи теперь живёт `wrapper`:

```python
@log_calls
def add(a, b):
    """Сложение двух чисел."""
    return a + b

add.__name__       # 'wrapper'  — а не 'add'
add.__doc__        # None       — докстринг пропал
```

Это ломает `help()`, логирование по `__name__`, отладчики и трейсбеки — везде
будет безликий `wrapper`. Лечится одной строкой — декоратором
`functools.wraps`, который копирует метаданные оригинала на обёртку:

```python
import functools

def log_calls(function):
    @functools.wraps(function)            # wrapper получает имя/докстринг function
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)
    return wrapper
```

**Правило: пишешь декоратор — ставь `@functools.wraps(function)` на обёртку.
Всегда.** Это бесплатно и избавляет от мистических `wrapper` в логах.

## 4. Реальные декораторы: @timer, @retry, @cache

Файл: [04_real_decorators.py](04_real_decorators.py)

Смысл декоратора — **вынести сквозную обвязку из тела функции**: замер времени,
повторы при сбоях, кеширование, логирование, проверка прав. Функция остаётся
про свою задачу, обвязка — одной строкой над `def`. Три классики:

### @timer — сколько работала функция

```python
@timer
def slow_sum(n):
    return sum(range(n))

slow_sum(10_000_000)     # печатает: slow_sum: 0.214 с
```

Внутри — `time.perf_counter()` до и после вызова. Полезен, чтобы быстро найти
узкое место без профайлера.

### @retry — повторить при сбое

Сетевые вызовы падают: таймаут, моргнул Wi-Fi, сервер вернул 500. Часто
достаточно просто **попробовать ещё раз**:

```python
@retry(attempts=3, delay=1.0)
def fetch_rate():
    ...                  # запрос к API, который иногда падает
```

Декоратор ловит исключение, ждёт `delay` секунд, пробует снова; после
`attempts` неудач — пробрасывает исключение наружу. Это декоратор **с
параметрами** — та самая трёхуровневая схема из темы 3.

### @cache — запомнить результат

Если функция **чистая** (одинаковые аргументы -> одинаковый результат) и
дорогая, её результаты можно запоминать. Свой декоратор писать не нужно — в
стандартной библиотеке есть готовые:

```python
import functools

@functools.lru_cache(maxsize=128)   # кеш с вытеснением старых записей
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```

`functools.cache` — то же без лимита (Python 3.9+). Наивный `fib(35)` делает
миллионы повторных вызовов; с кешем — 36. Ограничение: аргументы должны быть
**хешируемыми** (список передать нельзя), а для функций с побочными эффектами
кеш опасен — второй вызов просто не произойдёт.

Заметь общий принцип: ни `@timer`, ни `@retry`, ни `@cache` ничего не знают о
функциях, которые оборачивают. Один декоратор — десятки применений. В этом и
ценность.

# Блок 2. Парсинг HTML с BeautifulSoup

## 5. BeautifulSoup: дерево, CSS-селекторы, атрибуты

Файл: [05_bs4.py](05_bs4.py)

`BeautifulSoup` (пакет `beautifulsoup4`, импорт `bs4`) превращает строку HTML
в **дерево объектов**, по которому можно искать:

```python
from bs4 import BeautifulSoup

soup = BeautifulSoup(html, "html.parser")   # второй аргумент — парсер
```

`"html.parser"` — встроенный парсер из стандартной библиотеки, его хватает.
Есть и более быстрый `lxml`, но это отдельная зависимость.

### Поиск по CSS-селекторам

Главные два метода:

- `soup.select(селектор)` — **все** совпадения, возвращает список (возможно пустой);
- `soup.select_one(селектор)` — **первое** совпадение или `None`.

Сами селекторы — стандартные CSS, те же, что в DevTools браузера:

| Селектор             | Что найдёт                                  |
|----------------------|---------------------------------------------|
| `h3`                 | все теги `<h3>`                             |
| `.newsitem`          | теги с классом `newsitem`                   |
| `#newsbox`           | тег с `id="newsbox"`                        |
| `div.newsitem h3`    | `<h3>` внутри `<div class="newsitem">`      |
| `div > h3`           | `<h3>` — непосредственный ребёнок `<div>`   |
| `a[href]`            | ссылки, у которых есть атрибут `href`       |
| `a[rel="floatbox"]`  | ссылки с конкретным значением атрибута      |

Рабочий приём: открой страницу в браузере, правый клик по нужному элементу ->
«Просмотреть код», найди уникальный класс или `id` родителя — и собери селектор
от него. Проверить селектор можно прямо в DevTools: `Ctrl+F` в панели Elements.

### Текст и атрибуты

У найденного тега:

- `tag.text` — весь текст внутри, включая вложенные теги;
- `tag.get_text(strip=True)` — то же, с обрезкой пробелов и переводов строк;
- `tag["href"]` — значение атрибута; нет атрибута -> `KeyError`;
- `tag.get("href")` — то же, но нет атрибута -> `None` (как у словаря).

```python
for link in soup.select("div.nextnews a"):
    print(link.get_text(strip=True), "->", link["href"])
```

Ссылки в HTML часто **относительные** (`/press/news/31572.html`). Превратить в
абсолютную помогает `urllib.parse.urljoin(base_url, href)`.

### Откуда взять HTML: requests и кодировка

```python
import requests

response = requests.get(url, timeout=10)
html = response.text
```

- **`timeout` указывай всегда.** Без него зависший сервер повесит программу
  навечно. Истёк таймаут -> исключение `requests.exceptions.Timeout`
  (а недоступная сеть -> `ConnectionError`) — в практике их будет ловить декоратор.
- **Кодировка.** `requests` берёт её из HTTP-заголовка `Content-Type`. Если
  сервер прислал голый `text/html` без charset, `requests` подставит latin-1 — и
  русский текст превратится в кашу. Старые сайты (и наш сайт Коврова) живут в
  `windows-1251`. Лечение: выставить кодировку руками до обращения к `.text`
  (`response.encoding = "windows-1251"`) или отдать в `BeautifulSoup` сырые
  байты `response.content` — bs4 сам прочитает charset из `<meta>` страницы.

### Статика или JavaScript?

`requests` получает **исходный HTML**, JavaScript в нём никто не выполняет.
Если сайт рисует контент скриптами (типичная SPA), нужных данных в ответе не
будет — там пустые `<div>` и тонна `<script>`. Проверка перед работой:

```
curl -s https://kovrov-gorod.ru/ | head -100
```

Видишь в выдаче тексты новостей — статика, парсим `requests` + bs4. Не видишь —
ищи API, которым пользуется сам сайт (вкладка Network в DevTools), либо бери
браузерную автоматизацию (Selenium/Playwright — не в этом уроке).
Сайт Коврова — статика, нам повезло.

И про вежливость: не бомби сайт запросами в цикле — на время отладки скачай
страницу один раз и работай с локальной копией.

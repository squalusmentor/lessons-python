# Задание

Две небольшие практики — по одной на каждый блок урока.

## Часть 1. Погода через Open-Meteo

Мини-пайплайн: получить сырой JSON от погодного API, собрать из него плоский
словарь, напечатать сообщение из `**kwargs` и материализовать тот же словарь в
объект модели. Здесь сходятся все темы блока «функции вглубь»: сбор и
распаковка через `**kwargs`, словарь как набор «ключ → значение», объект как
конечная точка пайплайна.

[Open-Meteo](https://open-meteo.com) — бесплатный погодный JSON API, ключ не
нужен. Эндпоинт: `https://api.open-meteo.com/v1/forecast`, query-параметры:
`latitude`, `longitude`, `timezone` и `current` — список нужных полей через
запятую: `temperature_2m,relative_humidity_2m,apparent_temperature,wind_speed_10m,wind_direction_10m,weather_code,surface_pressure`.
Ответ отдаёт нужные текущие значения во вложенном ключе `current`.

Что написать:

1. **`fetch_weather(latitude, longitude)`** — запрос к API (`requests`,
   таймаут обязателен), возвращает сырой JSON как `dict`.
2. **`extract_fields(raw, city)`** — достаёт из `raw["current"]` нужные
   значения и собирает их в **один плоский словарь** с ключами: `city`, `time`,
   `temperature`, `feels_like`, `humidity`, `wind_speed`, `wind_direction`,
   `pressure`, `description`. Код погоды (`weather_code`) — целое число по
   стандарту WMO, его нужно превратить в текстовое описание самому (заведи
   словарь-справочник хотя бы для нескольких кодов, например: `0` — ясно,
   `1`–`2` — переменная облачность, `3` — пасмурно, `45` — туман, `61`–`65` —
   дождь, `71`–`75` — снег, `95` — гроза; для кода, которого нет в справочнике,
   верни «неизвестно»).
3. **`build_message(**fields)`** — принимает данные через `**kwargs` и
   собирает читаемое сообщение-строку (никуда не отправляем). Вызов
   `build_message(**fields)` — это распаковка словаря в именованные аргументы.
4. **`WeatherData`** — маленький класс, у которого `__init__` принимает ровно
   те же именованные параметры, что в плоском словаре, чтобы объект создавался
   одной распаковкой: `WeatherData(**fields)`.

Один и тот же словарь данных должен и печататься (`build_message(**d)`), и
материализовываться в объект (`WeatherData(**d)`) — это и есть цель практики.

## Часть 2. Свой `tree`

Аналог консольной команды `tree`: рекурсивный обход директории с печатью
дерева файлов и папок с отступами по глубине. Идеальная задача для рекурсии —
глубина вложенности папок заранее неизвестна.

Функция `print_tree(path, depth=0)`:

- печатает имя текущего элемента с отступом, зависящим от `depth` (папке можно
  добавить `/` в конце для наглядности);
- **база**: если `path` — файл, на этом всё;
- **шаг**: если `path` — директория, перебери её содержимое (`path.iterdir()`,
  отсортированное для стабильного порядка) и вызови `print_tree` для каждого
  элемента с `depth + 1`.

Работай через `pathlib.Path` (`path.name`, `path.is_dir()`, `path.iterdir()`).
Базовая версия — отступы пробелами; кто хочет сложнее — можно нарисовать
настоящие рамки `├──`, `└──`, `│`, как у реального `tree`.

# Задание: асинхронный чекер сайтов

Проверяем пачку URL **конкурентно** на `aiohttp` и сравниваем со старым
синхронным подходом на `requests`. Для каждого URL нужно узнать HTTP-статус,
размер ответа и сколько секунд занял запрос. Синхронно это тянется по
очереди — суммарное время складывается. Асинхронно все запросы летят
конкурентно на одном потоке — общее время падает примерно до самого долгого
ответа. Задача — увидеть эту разницу вживую, на цифрах.

Тестовый набор URL — сервис [httpbin.org](https://httpbin.org), который умеет
отвечать с заданной задержкой: `https://httpbin.org/delay/N` отвечает через
`N` секунд. Возьми штук 5–7 URL с разными задержками (1–3 секунды) плюс
пару обычных (`https://httpbin.org/status/200`, `.../status/404`), чтобы
разница sync/async была заметна и на глаз, и в цифрах.

## Часть 1. Синхронный эталон

Обычная функция на `requests`, которая по очереди опрашивает список URL и для
каждого возвращает словарь `{"url", "status", "size", "elapsed"}` (`elapsed` —
время одного запроса в секундах, округлённое). Она нужна как база для
сравнения — засеки суммарное время по всему списку: оно должно быть примерно
равно **сумме** задержек всех URL.

## Часть 2. Асинхронная версия на aiohttp

**`check(session, url, semaphore)`** — корутина, проверяет один `url`.
Принимает уже готовую `aiohttp.ClientSession` (сессию не создавай внутри — она
должна быть одна на все запросы, см. часть 3) и `asyncio.Semaphore`. Поведение:

- работает под `async with semaphore:` — так ограничивается число
  одновременных запросов;
- засекает время (`time.perf_counter`);
- делает запрос через `session.get(url)`, читает тело (`await response.read()`,
  нужен размер в байтах);
- возвращает словарь того же вида, что и синхронная версия;
- ошибки не должны ронять весь чекер — поймай `aiohttp.ClientError` и
  `asyncio.TimeoutError`, верни для такого URL словарь со `"status": "error"`
  и деталями исключения вместо падения.

## Часть 3. `check_all_async(urls, limit=5)`

- одна **сессия** на все запросы: `async with aiohttp.ClientSession(timeout=...) as session:`
  (задай общий таймаут через `aiohttp.ClientTimeout`) — сессия переиспользует
  пул соединений, создавать новую на каждый запрос — антипаттерн;
- один **семафор**: `asyncio.Semaphore(limit)` — не больше `limit` запросов в
  полёте одновременно. Без него на большом списке URL можно упереться в лимиты
  ОС или разозлить сервер — это классический приём backpressure в async;
- собери корутины `check(...)` для всех URL и запусти их конкурентно через
  `asyncio.gather`, верни список результатов.

## Часть 4. `demo()`

1. Прогони синхронную версию, напечатай суммарное время.
2. Прогони `asyncio.run(check_all_async(urls))`, напечатай суммарное время.
3. Построчно напечатай результаты async-версии.
4. Посчитай и напечатай ускорение — во сколько раз async оказался быстрее
   (`sync_time / async_time`).

Ожидаемо: время синхронной версии ≈ сумма задержек, время асинхронной ≈ самая
долгая из них.

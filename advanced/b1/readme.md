# Блок 1. Функции вглубь

## 1. `*args` и `**kwargs`

Это два механизма: **сбор** аргументов в сигнатуре и **распаковка** при вызове.
Одна и та же звёздочка работает в обе стороны.

**Сбор** (в объявлении функции):

- `*args` — собирает оставшиеся **позиционные** аргументы в **кортеж**.
- `**kwargs` — собирает оставшиеся **именованные** аргументы в **словарь**.

Имена `args`/`kwargs` — лишь договорённость; важны сами `*` и `**`. Кортеж может
быть пустым — это нормально.

**Распаковка** (в месте вызова):

- `*` разворачивает список/кортеж в позиционные аргументы: `f(*[1, 2, 3])` ≡ `f(1, 2, 3)`.
- `**` разворачивает словарь в именованные: `f(**{"a": 1})` ≡ `f(a=1)`.

Полная сигнатура подчиняется **строгому порядку**:

```python
def f(pos, *args, kw_only, **kwargs): ...
#     обычные  ↑      ↑        ↑
#         позиц.  только по   всё
#                  имени      остальное именованное
```

Параметры **после** `*args` (или после одинокой `*`) становятся
**только-именованными** — их нельзя передать по позиции. Зеркально, `/` в
сигнатуре делает параметры слева от себя **только-позиционными**:

```python
def connect(host, port, /, *, secure=True): ...
#           только по позиции  только по имени
```

Проброс `*args, **kwargs` дальше в другую функцию — это фундамент **обёрток и
декораторов**: обёртка принимает что угодно и передаёт без изменений:

```python
def logged(func, *args, **kwargs):
    print("вызов", func.__name__)
    return func(*args, **kwargs)   # отдаём аргументы как есть
```

## 2. Область видимости (правило LEGB)

Когда Python встречает имя, он ищет его в четырёх областях **по порядку**:

- **L**ocal — локальные имена текущей функции;
- **E**nclosing — имена объемлющей функции (для вложенных функций);
- **G**lobal — имена уровня модуля;
- **B**uilt-in — встроенные (`len`, `print`, `range`, …).

Нашёл — остановился. Не нашёл нигде — `NameError`.

**Ключевая ловушка**: **присваивание** делает имя **локальным** для всей функции.
Поэтому такой код падает:

```python
counter = 0
def f():
    print(counter)   # UnboundLocalError!
    counter = 1      # из-за этой строки counter локальный во ВСЁЙ функции
```

**Читать** глобальную переменную можно без объявлений. А чтобы **присвоить**
глобальной (а не создать локальную), нужно явно сказать `global имя`. Для
переменной из объемлющей функции — `nonlocal имя` (см. замыкания).

Ещё одна ловушка — **тень над встроенными**: `list = [1, 2, 3]` внутри функции
перекрывает тип `list`, и вызвать `list(...)` уже не получится. Поэтому не называй
переменные `list`, `dict`, `str`, `id`, `sum`, `type`.

Мелочь, но полезная: переменная цикла внутри **comprehension** живёт в своей
области и **не утекает** наружу (в отличие от обычного `for`).

## 3. Замыкания

Вложенная функция **видит** переменные объемлющей — и они продолжают жить вместе с
ней даже после того, как внешняя функция завершилась. Это и есть **замыкание**.

```python
def multiplier(factor):
    def inner(x):
        return x * factor   # factor захвачен из multiplier
    return inner             # возвращаем функцию; factor живёт вместе с ней

double = multiplier(2)
double(5)   # 10
```

Чтобы **изменять** захваченную переменную (а не создавать новую локальную),
объявляют `nonlocal`. Классический пример — счётчик с собственным состоянием:

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc
```

У каждого вызова `make_counter()` — **своё** независимое состояние. Это «состояние
без класса»; на замыканиях держатся декораторы (следующий урок).

**Ловушка позднего связывания.** Замыкание захватывает **переменную**, а не её
значение в момент создания. Поэтому лямбды, созданные в цикле, видят **последнее**
значение переменной:

```python
funcs = [lambda: i for i in range(3)]
[f() for f in funcs]   # [2, 2, 2], а НЕ [0, 1, 2]
```

Чинят захватом значения через аргумент по умолчанию (он вычисляется сразу):

```python
funcs = [lambda i=i: i for i in range(3)]   # [0, 1, 2]
```

## 4. Функции как объекты первого класса

В Python функция — **обычный объект**: её можно положить в переменную, передать
аргументом, вернуть из другой функции, сложить в список или словарь, навесить
атрибут. «Первоклассность» означает именно это.

```python
f = add          # без скобок — берём саму функцию, не вызываем
f(2, 3)          # 5
f.__name__       # 'add'
```

Функции, которые **принимают или возвращают** другие функции, называют
**функциями высшего порядка** (higher-order). Встроенные примеры —
`map`, `filter`, `sorted(key=...)`, `functools.reduce`.

```python
sorted(words, key=len)               # сортировка по длине
list(map(lambda x: x*x, nums))       # квадраты
list(filter(lambda x: x % 2 == 0, nums))  # только чётные
```

Очень частый паттерн — **таблица диспетчеризации**: словарь `"имя" -> функция`
вместо длинной цепочки `if/elif`:

```python
OPERATIONS = {"+": add, "-": sub, "*": mul}
OPERATIONS[op](a, b)
```

## Практическая работа 1 — погода через Open-Meteo

Файл: [practice_weather.py](practice_weather.py). Решение: [solutions/practice_weather_solution.py](solutions/practice_weather_solution.py).

[Open-Meteo](https://open-meteo.com) — бесплатный погодный API без ключа. Он отдаёт
**JSON** (а не HTML), поэтому ничего не «парсим» в смысле bs4 — JSON сразу
превращается в словарь Python. Задача — собрать мини-пайплайн, в котором сходятся
все темы блока:

1. `fetch_weather(lat, lon)` (дано) — делает запрос к API и возвращает сырой JSON
   как `dict`. Без сети берёт вшитый `SAMPLE_RESPONSE` — реальный ответ по Москве.
2. **TODO `extract_fields(raw, city)`** — достаёт нужные значения из вложенного
   `raw["current"]` и собирает их в **один плоский словарь** «ключ → значение».
   Код погоды (`weather_code`) превращает в текст по справочнику `WMO_DESCRIPTIONS`.
3. **TODO `build_message(**fields)`** — принимает данные через `**kwargs` и
   собирает читаемое **сообщение** (никуда не отправляем — просто строка). Вызов
   `build_message(**fields)` показывает **распаковку** словаря в именованные аргументы.
4. `WeatherData(**fields)` (класс дан) — тот же словарь распаковывается в **объект
   модели**. Ключи плоского словаря специально совпадают с именами параметров
   `__init__`, поэтому объект создаётся одной распаковкой. БД пока нет — но объект
   уже «живёт» в памяти и ждёт `save()`.

Главная мысль: один и тот же словарь данных мы и печатаем (`build_message(**d)`), и
материализуем в объект (`WeatherData(**d)`) — всё на механике `**kwargs`.

# Блок 2. Рекурсия

**Рекурсия** — это когда функция вызывает саму себя на задаче поменьше. У любой
корректной рекурсии две части:

- **База** — условие, при котором функция возвращает ответ **без** вызова себя.
  Без базы будет бесконечный спуск.
- **Шаг** — вызов себя на «уменьшенной» задаче, приближающий к базе.

```python
def factorial(n):
    if n <= 1:          # база
        return 1
    return n * factorial(n - 1)   # шаг
```

### Стек вызовов и лимит глубины

Каждый вызов кладёт на **стек вызовов** новый кадр (фрейм) с локальными
переменными. Возврат — снимает кадр. В Python глубина стека ограничена: по
умолчанию ~**1000** вложенных вызовов, дальше — `RecursionError`. Текущий лимит —
`sys.getrecursionlimit()`, поднять — `sys.setrecursionlimit(...)` (осторожно: можно
уронить интерпретатор переполнением реального стека).

**Хвостовой оптимизации (TCO) в Python нет** и не будет — это осознанное решение
Гвидо. Поэтому **глубокую линейную** рекурсию (миллион уровней) переписывают
**итеративно** или через явный стек. Рекурсию оставляют там, где она реально
выигрывает в читаемости.

### Где рекурсия естественна

- **Вложенные/древовидные структуры**: дерево файлов, вложенные списки, JSON,
  HTML-дерево, дерево комментариев. Глубина заранее неизвестна — цикл тут громоздкий.
- **Разделяй и властвуй**: быстрая сортировка, бинарный поиск, обход дерева.

### Медленная рекурсия и мемоизация

Наивные числа Фибоначчи (`fib(n) = fib(n-1) + fib(n-2)`) пересчитывают одно и то же
**экспоненциальное** число раз. Лечится **мемоизацией** — кэшем результатов по
аргументам. В стандартной библиотеке это одна строка-декоратор:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```

## Практическая работа 2 — свой `tree`

Файл: [practice_tree.py](practice_tree.py). Решение: [solutions/practice_tree_solution.py](solutions/practice_tree_solution.py).

Реализуй аналог консольной команды `tree` — рекурсивный обход директории с печатью
дерева файлов и папок с **отступами**. Это идеальная задача для рекурсии: глубина
вложенности папок заранее неизвестна.

Алгоритм:

- **печатаем** имя текущего элемента с отступом по глубине;
- **база**: элемент — файл → выходим;
- **шаг**: элемент — папка → перебираем `sorted(path.iterdir())` и вызываем себя для
  каждого вложенного элемента с `depth + 1`.

Базовая версия делает отступы пробелами. В решении показана и «настоящая» версия с
рамками `├──`, `└──`, `│` — как у реального `tree`. Работаем через `pathlib.Path`
(`path.name`, `path.is_dir()`, `path.iterdir()`).

# Задание: сервис «Часы»

Напиши на FastAPI маленький сервис, который по `GET`-запросу отдаёт **текущее
время** в указанном часовом поясе. Часовой пояс передаётся в **query-параметрах**
запроса. Базы данных нет — время берётся из системных часов прямо сейчас.

Главное условие: собери сервис **с тем же разделением на слои**, что и пример
урока (`main` -> `routers` -> `handlers` -> `services` -> `schemas`). Логику не
сваливай в один файл.

## Что должен уметь сервис

### `GET /time` — текущее время в часовом поясе

- Часовой пояс — в query-параметре `tz`, например:

  ```
  GET /time?tz=Europe/Moscow
  GET /time?tz=Asia/Tokyo
  GET /time?tz=UTC
  ```

- Если `tz` не передан — по умолчанию `UTC`.
- Успех (`200`) — JSON с текущим временем, например:

  ```json
  {
    "timezone": "Europe/Moscow",
    "datetime": "2026-06-29T17:45:12+03:00",
    "time": "17:45:12",
    "date": "2026-06-29"
  }
  ```

- Неизвестный часовой пояс (`?tz=Mars/Olympus`) — ответ `404` (или `400`) с
  понятным `detail`, например `{"detail": "Unknown timezone"}`.

## Требования

- **Слои как в уроке.** Минимум:
  - `main.py` — создаёт `app`, подключает роутер, запускает uvicorn;
  - `routers/` — объявляет `GET /time`, забирает query-параметр `tz`, задаёт
    `response_model`;
  - `handlers/` — решает, что делать; бросает `HTTPException(404)` на неизвестный пояс;
  - `services/` — вычисляет текущее время для переданного пояса (вся работа со
    временем — здесь);
  - `schemas/` — pydantic-схема ответа (`TimeResponse`).
- Запуск: `uvicorn main:app --reload`.
- Эндпоинт проверяется из Swagger UI (`/docs`).
- `requirements.txt` — как минимум `fastapi`, `uvicorn[standard]`.
- Осмысленные коммиты в git (`init`, `add GET /time`, `handle unknown tz`).

## Подсказки

- Часовые пояса бери из **стандартной библиотеки** — `datetime` и `zoneinfo`
  (`ZoneInfo`, `ZoneInfoNotFoundError`), ставить ничего не надо. `datetime`
  умеет вернуть текущее время сразу с учётом пояса, если передать ему объект
  `ZoneInfo`; из готового `datetime` дальше достаются и ISO-строка, и время, и
  дата по отдельности.
- Неизвестный часовой пояс роняет `ZoneInfoNotFoundError` — поймай его и
  преврати в `HTTPException(status_code=404, ...)`. Помни из теории урока:
  бизнес-логика и коды ошибок — забота **хендлера**, а не роутера.
- Query-параметр `tz` — это просто аргумент функции-роута, которого нет в
  пути; значение по умолчанию делает его необязательным.

## Со звёздочкой (по желанию)

- Добавь эндпоинт `GET /timezones` — список доступных поясов
  (`zoneinfo.available_timezones()`), чтобы клиент знал, что можно спросить.
- Добавь параметр формата: `?format=12h|24h` — отдавать время в 12- или
  24-часовом виде. Заодно потренируешь валидацию query-параметра.

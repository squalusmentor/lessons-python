# Урок B4. FastAPI на боевом примере: JWT, БД, Docker

Теория HTTP, REST, эндпоинтов, роутов и разделения на слои уже пройдена в
`B2` — там же разобрано, почему эндпоинты `async def` (event loop и GIL). Здесь
её незачем повторять: вместо этого смотрим, как та же архитектура выглядит на
**настоящем** приложении — с базой данных, JWT-авторизацией и Docker.

Проект — целиком реальный бэкенд тестового задания автора курса: регистрация,
JWT-авторизация, пользователи и статьи, PostgreSQL через async-драйвер
(`asyncpg` + SQLAlchemy — та же связка, что в `B3`). Это не учебный пример
«для урока», а код, который решал настоящую задачу — поэтому он живёт в
собственном репозитории, а не встроен в этот урок.

Главная мысль урока та же, что в `B2`: **API — это контракт.** URL говорит
«над каким ресурсом», HTTP-метод — «что с ним сделать», тело запроса — «с
какими данными», код ответа — «чем кончилось». Разница только в масштабе: тут
контракт держат сразу три ресурса (`auth`, `users`, `articles`), а не один.

## Как запустить

Нужны установленные Docker и Docker Compose. Дальше — по `README.md` в самом
склонированном репозитории: скопировать `.env-example` в `.env`, поднять
`docker compose build && docker compose up`, открыть Swagger UI на `/docs`.
`SEED_DB=true` в `.env` заполнит базу тестовыми пользователями и статьями.

## Что посмотреть в коде в первую очередь

Один вертикальный срез — маршрут, логика, форма данных — показывает всю схему
слоёв сразу:

```
backend/main.py
  -> backend/source/routers/users.py
  -> backend/source/handlers/users.py
  -> backend/source/schemas/user.py
```

Дальше — то, чего не было в `B2`:

- `backend/source/models/` — таблицы SQLAlchemy (`User`, `Article`), связаны
  через `owner_id` — ровно та связь один-ко-многим, что разбиралась в `B3`.
- `backend/source/db.py` / `db_connect.py` — движок, фабрика сессий,
  `connect_with_retry()` — подключение к БД с несколькими попытками (при
  старте через Docker Compose приложение поднимается раньше, чем сама база).
- `backend/source/services/scripts.py` — выпуск и проверка JWT-токена.
- Хендлеры (`backend/source/handlers/users.py`) — разграничение прав: чужой
  профиль обычному пользователю -> `403`, несуществующий пользователь -> `404`.

## Что дальше

Ты видел, как теория из `B2` (слои, роуты, схемы) и `B3` (асинхронная ORM)
выглядит в реальном приложении, плюс — JWT-авторизацию и Docker. Следующий
уровень — миграции (Alembic вместо `create_all`), пагинация и фильтры,
индексы. Всё это навешивается на тот же движок и те же слои, что уже видел
здесь и в `B3`.

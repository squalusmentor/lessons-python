## 1. Итераторы: что происходит внутри for

Файл: [01_iterators.py](01_iterators.py)

Сначала разведём три понятия, которые обычно путают:

| Термин | Простыми словами | Примеры |
|---|---|---|
| **iterable** (итерируемое) | то, **по чему** можно пройти | список, строка, словарь, файл, `range` |
| **iterator** (итератор) | тот, **кто** идёт: помнит позицию, умеет `next()` | результат `iter(...)`, любой генератор |
| **`for`** | цикл, который делает всё это за тебя | `for x in numbers:` |

Когда ты пишешь `for`, Python делает ровно три вещи:

1. просит у объекта итератор — `iter(numbers)`;
2. в цикле дергает `next(it)`, пока значения не кончатся;
3. поймав `StopIteration`, тихо выходит из цикла.

```python
numbers = [10, 20, 30]

it = iter(numbers)
next(it)        # 10
next(it)        # 20
next(it)        # 30
next(it)        # StopIteration — значения кончились
```

`StopIteration` — не ошибка, а штатный сигнал «всё, я закончил». `for` его ловит
сам, поэтому ты его обычно и не видишь.

### Итератор одноразовый

Самое важное практическое следствие. Итератор помнит, где остановился, и назад
не отматывается:

```python
it = iter([1, 2, 3])
list(it)        # [1, 2, 3]
list(it)        # []  <- пусто, итератор израсходован
```

По **списку** можно ходить сколько угодно раз (`for` каждый раз берёт новый
итератор), а по **итератору** — только один. Отсюда классическая ошибка: посчитал
`sum(...)`, потом захотел `max(...)` по тому же объекту — и получил пустоту.

### Зачем это на практике: файл — это итератор строк

Самый частый случай, где теория превращается в рабочий код. Открытый файл — это
готовый итератор строк, поэтому по нему можно просто идти циклом:

```python
with open("data.txt", encoding="utf-8") as f:
    for line in f:                 # файл выдаёт строки ПО ОДНОЙ
        print(line.strip())        # в памяти одна строка

with open("data.txt", encoding="utf-8") as f:
    lines = f.readlines()          # а тут файл целиком загружен в память
```

На файле в три строки разницы нет. На файле в 2 ГБ первый вариант спокойно
работает, второй кладёт программу по нехватке памяти. Это не «оптимизация для
больших проектов», а обычный способ читать файлы.

Так же устроены `zip`, `enumerate`, `map`, `filter`, `csv.reader`, курсор БД:
всё это итераторы, а не списки. Отладочный `print(list(rows))` перед циклом
израсходует такой объект — и цикл ниже не выполнится ни разу, без единой ошибки
в консоли. Нужны данные несколько раз — сохрани их в список.

### Свой итератор: `__iter__` и `__next__`

Чтобы твой объект работал в `for`, ему нужны всего два метода:

```python
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):            # вернуть итератор (здесь — сам объект)
        return self

    def __next__(self):            # выдать следующее значение...
        if self.current < 1:
            raise StopIteration    # ...или сказать, что всё кончилось
        value = self.current
        self.current -= 1
        return value

for n in Countdown(3):
    print(n)                       # 3, 2, 1
```

Работает — но двенадцать строк ради обратного отсчёта. Дальше то же самое
уместится в две.

## 2. Генераторы: то же самое через yield

Файл: [02_generators.py](02_generators.py)

**Генератор — это функция, в которой вместо `return` стоит `yield`.** Такая
функция при вызове не выполняет тело, а возвращает готовый итератор:

```python
def countdown(start):
    while start > 0:
        yield start        # выдали значение и встали на паузу
        start -= 1
```

Весь класс из темы 1 — в трёх строках. `yield` отдаёт одно значение и
**замораживает функцию** на этом месте; следующий `next()` продолжает с той же
строки, со всеми локальными переменными на месте. Дошли до конца функции —
генератор сам бросает `StopIteration`.

### Ленивость — то, за что генераторы и любят

Вызов генераторной функции **не выполняет ни одной строки её тела**:

```python
def noisy():
    print("начало тела")
    yield 1

gen = noisy()      # ничего не напечаталось!
next(gen)          # вот теперь: "начало тела", затем 1
```

Значения считаются по требованию, по одному. Что это даёт на практике:

- **Память не зависит от объёма данных.** Список на миллион чисел — около 8 МБ
  (и это только сам список, без самих чисел). Генератор — около 200 байт,
  независимо от того, миллион там значений или миллиард.
- **Первый результат приходит сразу.** Не надо ждать, пока обработается весь
  файл, чтобы увидеть первую строку.
- **Данные могут не кончаться вовсе.** Бесконечный генератор — совершенно
  нормальная вещь:

```python
def new_id(start=1):
    while True:            # бесконечный цикл здесь безопасен:
        yield start        # значения выдаются только когда их просят
        start += 1
```

### Чего генератор не умеет

| Что | Почему |
|---|---|
| `len(gen)` | длина заранее неизвестна — значения ещё не посчитаны |
| `gen[0]`, срезы | нет индексов, только «следующее значение» |
| `print(gen)` покажет данные | напечатает `<generator object ...>`; нужен `list(gen)` |
| пройти дважды | генератор — итератор, а он одноразовый |

Нужен полноценный набор — оберни в список: `list(gen)`. Но тогда, разумеется,
пропадает и экономия памяти. **Правило: нужны все значения сразу, по индексу или
несколько раз — список; надо пройти один раз, данных много или они бесконечны —
генератор.**

## 3. Генераторные выражения

Файл: [03_genexp.py](03_genexp.py)

Списочное включение ты знаешь. Замени квадратные скобки на круглые — получится
генератор:

```python
[x * x for x in range(5)]      # список: [0, 1, 4, 9, 16], всё уже в памяти
(x * x for x in range(5))      # генератор: значений пока нет вообще
```

Синтаксис почти тот же, поведение — разное. Самое частое применение: отдать
генераторное выражение функции, которая всё равно пройдёт по нему один раз.
Скобки при этом не дублируются:

```python
sum(x * x for x in range(1_000_000))            # ни одного списка не создано
max(len(word) for word in words)
any("ошибка" in line for line in lines)         # остановится на первом же True
all(price > 0 for price in prices)
", ".join(user.name for user in users)
```

`any` и `all` вдобавок **ленивые в другом смысле**: они прекращают проверку на
первом ответе. `any(...)` по миллиону строк, где нужная встретилась второй, —
это две проверки, а не миллион.

Фильтр пишется через `if` справа:

```python
errors = (line for line in lines if "ERROR" in line)
```
